## Qualtrics pilot survey built (afternoon)

Built the EARS Pilot v1 survey on DW's new Tulane Qualtrics account, programmatically via the v3 API. Survey ID `SV_ahjVK84570ekXFY` in the `co1` datacenter (note: the Account Settings page shows datacenter `iad1`, but the API's whoami endpoint reports `co1`. The API responds at both subdomains but we use co1 per its own report).

Design (locked in by DW):
- All 297 Loughran-McDonald Uncertainty words rated by every subject (within-subject)
- Two unipolar 7-point Likert scales per word: epistemic intensity and aleatory intensity (matrix Likert with two statements per word)
- Force-response OFF (subjects can skip if unfamiliar with a word)
- Brief construct tutorial up front (definitions + examples mirror `docs/construct_definitions.md`)
- Generic Tulane consent placeholder (must be replaced with IRB-approved text before activation)
- Demographics: age (numeric), gender, education, native English speaker, unknown-words open text, general feedback
- Created in Inactive state; no responses can be collected until activated
- Estimated subject burden: ~25-30 min

Build pipeline:
- `scripts/qualtrics/build_pilot_v1.py` — main builder (5 blocks, 297 word questions, demographics)
- `scripts/qualtrics/fix_pilot_v1.py` — patches the two issues from the initial build (age question validation schema, attempt at randomization)
- `outputs/survey/pilot_v1_metadata.json` — survey ID, block IDs, preview URL, manual steps required
- `outputs/survey/pilot_v1_build.log` — full build log

API quirks discovered (and worked around):
1. `Validation.Settings.Type = "ValidNumber"` is rejected. Must use `ContentType` with nested `ContentType: "ValidNumber"`. Fixed in patch script.
2. Block-level question randomization cannot be enabled via the v3 block PUT endpoint — Qualtrics rejects all values for `RandomizeQuestions` other than `""` or `"False"`. Documented as a manual one-click step in the web editor before activation.
3. Question ordering within a block: new questions append to the end, so the age question (added via patch) ended up at the bottom of Demographics. Manual reorder needed in the editor.

Token security: the API token is read from `QUALTRICS_TOKEN` environment variable. Not committed to git; not synced to OSF. The token is in DW's chat with this session and on his Qualtrics Account Settings page only.

## Protocol v2.0 committed (2026-04-29 follow-up)

Replaced v1.0 of `docs/expansion_protocol.md` with a simplified v2.0. Scope shift:

- **Input:** 297 LM words directly (no five-method candidate generation)
- **Method:** LLM ensemble classification with corpus-grounded KWIC contexts
  - 5 prompt variants (strict / chain-of-thought / expert-frame / conservative / phrase-aware)
  - Each rater sees 5 real usage contexts from the earnings-call corpus
  - Aggregate by majority vote (>= 4 of 5 for high-confidence accept)
  - Krippendorff's alpha across the 5 raters
- **Calibration:** the 8 words in v1 EARS ∩ LM 297 act as held-in ground truth (>= 7 of 8 must classify correctly to proceed)
- **Validation:** held-out 30% of transcripts (split by firm, stratified by surprise) for convergent validity, predictive validity, leave-one-out robustness, top-3 concentration

Considered and cut from a parallel CG-LET draft: FinBERT embedding-based classifier and method triangulation. Cut for simplicity at DW's instruction; v1 EARS calibration check substitutes as the independent ground truth.

DW requested an independent agent evaluation of v2.0 before execution. That evaluation is in flight.
